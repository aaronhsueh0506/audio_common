audio_common C API 使用說明

本頁是整合者視角的 API 說明。audio_common 是 AEC／NR／pipelines 共用的底層 DSP 層,其中只有五個 header 是給整合者用的,其餘是共用實作細節。canonical 出處是 audio_common/docs/c_user_manual_zh_TW.md。

1. 十個 header,先分清楚哪些該碰

Header分類什麼時候需要
fft_wrapper.h整合者面向只要 FFT 本身時(組幀與 overlap-add 請用 audio_stft.h)。也是 NR 的 Complex 型別來源
audio_stft.h整合者面向自己要做 sqrt-Hann STFT／ISTFT(50% overlap 的組幀、加窗、overlap-add)時
audio_resampler.h整合者面向擷取取樣率 ≠ 處理取樣率時
hpf.h整合者面向要在 AEC 之外做高通時(AEC 內建 mic-path HPF,見下)
audio_pre_gain.h整合者面向輸入電平調整
mem_align.h半公開只有「自己也要從同一塊 pool 切物件」或自算 pool 總需求時。單純呼叫別人的 _get_mem_size+_init 不需要
simd_kernels.h內部/共用核心一般整合者不呼叫。只有自己寫的熱迴圈剛好與某個核心形狀完全一致時才考慮
simd_kernel_nn.h內部/共用核心神經網路模型前後處理與重取樣器專用的 skn_* 核心(與 simd_kernels.h 分開管理,傳統 AEC/NR 不引用)。一般整合者不呼叫
fast_math.h內部/共用同上。超出定義域回固定邊界常數而非 IEEE 語意(例:fast_sqrt(NaN) 回 0.0f)
wav_io.h離線工具專用不適合即時/嵌入式路徑(用 stdio + malloc,每樣本一次 fread/fwrite)
若你的 TU 直接 include 了 simd_kernels.h 或 fast_math.h,必須加 -ffp-contract=off(放 CFLAGS 最後),否則你的 TU 與 archive 內同名邏輯的浮點捨入路徑會不一致。這兩個 header 的所有核心都是 void、不檢查 NULL/範圍、沒有錯誤通道。

2. 共通的 static-pool 模式

五個整合者面向的模組(以及 AEC／NR)全部遵守同一個模式:

config → get_mem_size() → caller 配置「至少 16-byte 對齊」的 pool
       → init(pool, bytes, ...) → process...（不可 malloc）
       → reset（需要時）→ destroy（不釋放 caller pool）→ caller 釋放 pool
規則細節
對齊16 bytes,由 MEM_IS_ALIGNED16 在每個 _init() 進入點檢查,未對齊一律回 NULL
heap vs pool兩條路徑同時存在於同一份 object,handle 內部 flag 決定 destroy() 要不要 free()。pool 路徑的 destroy 是 no-op、可重複呼叫;heap 路徑只能呼叫一次
有狀態物件必須存活整段串流AudioResampler／Hpf／FftHandle／AcStft／AcIstft 不要逐 block 重建
溢位mem_align.h 的 ck_add_size／ck_mul_size／ck_align16_size／ck_field_size 是飽和算術,任一步溢位就飽和到 SIZE_MAX 並一路傳遞,走訪結尾用 MEM_SIZE_INVALID() 檢查一次

3. fft_wrapper.h — FFT 包裝層

size_t     need = fft_get_mem_size(256);        /* 0 = fft_size 不合法 */
FftHandle *fft  = fft_init(pool16, need, 256);  /* 或 fft_create(256) 走 heap */

float   time[256];
Complex bins[129];                              /* n_freqs = 256/2+1 */

fft_forward(fft, time, bins);                   /* real → complex */
fft_inverse(fft, bins, time);                   /* complex → real,已含 1/N */

fft_destroy(fft);
項目契約
fft_size 範圍2 的次方且 [16, 8192]。超出(含 8 或 16384)一律回 NULL／0
Scaling:誰除以 Nfft_forward = 未正規化;fft_inverse = 已含 1/N。不要再自己除一次
Aliasing參數帶 restrict → 任何重疊都是 UB,包含傳入完全相同的指標
pool 內容fft_get_mem_size() 已包含後端的 twiddle/config → fft_init() 之後不會再向 heap 要記憶體
省一次複製輸入是可破壞的 scratch 時用 fft_forward_scratch()／fft_inverse_scratch(),呼叫後輸入內容未定義
Aliasing 規則與 NR 相反。NR 的 anr_process() 明確支援 out == in(完全同一指標);FFT 這裡則是任何重疊都 UB。兩層不要套用同一條直覺。

其他:fft_magnitude／fft_power(較便宜,不開根號)／fft_phase／fft_from_mag_phase／fft_apply_gain(就地)。

Backend 是編譯期決定的

BACKEND說明
ne10ARM NEON,嵌入式交付品。靠編譯期巨集 NE10_DSP_RFFT_SCALING 自動做 1/N——該巨集在 Makefile 裡強制打開,不可關掉
kiss可攜、可位元重現。手動乘 1.0f/n
兩個後端的輸出不是逐位元相同(不同 FFT 實作)。位元級回歸比對必須兩邊同後端;也不要混連不同 BACKEND 的產物。

3b. audio_stft.h — sqrt-Hann STFT／ISTFT

AcStftConfig cfg;
ac_stft_config_default(&cfg, 512);              /* hop = 256 */
size_t sa = ac_stft_get_mem_size(&cfg);         /* 0 = 設定不合法 */
size_t ss = ac_istft_get_mem_size(&cfg);
AcStft  *an  = ac_stft_init(pool_a16, sa, &cfg);    /* NULL = 失敗 */
AcIstft *syn = ac_istft_init(pool_s16, ss, &cfg);

Complex spec[2 * 257];                          /* center = 1 時一次最多 2 幀 */
float   hop_in[256], hop_out[256];

int n = ac_stft_push(an, hop_in, spec);         /* 回傳幀數;幀 f 在 spec + f * 257 */
/* ... 處理 spec ... */
for (int f = 0; f < n; ++f)
    ac_istft_push(syn, spec + f * 257, hop_out);   /* 回傳寫出的樣本數(hop 或 0) */
項目契約
設定AcStftConfig:fft_size(2 的冪、[16, 8192],hop = fft_size/2)、center(0／1,只影響 AcStft)、ola(AC_OLA_ACCUMULATE／AC_OLA_ENV_NORM,只影響 AcIstft)、spec_scale／ispec_scale、fft／window(借用或 NULL)。用 ac_stft_config_default() 起手,再改要改的欄位
窗只有一種:週期 sqrt-Hann sqrtf(0.5f*(1.0f-cosf(2.0f*pi*k/N)));ac_window_build(w, n) 可單獨建表,ac_stft_window()／ac_istft_window() 取得使用中的表
縮放spec_scale 乘在前向 FFT 輸出的每個 bin;ispec_scale 乘在反向 FFT 輸入的每個 bin。恰為 1.0f 時略過乘法(精確搬移)。FFT 本身仍是前向未正規化、反向含 1/N
借用 vs 自帶cfg.fft／cfg.window 為 NULL 時從 pool 切出自己的(get_mem_size 已含);非 NULL 時借用:handle 的 n_freqs 必須等於 fft_size/2+1(否則 get_mem_size 回 0、init 回 NULL),窗表須維持不變且活得比物件久;一支 handle 可被多個物件共用(呼叫須循序、不可並行)
AcStft 輸出幀數center = 0:每次 push 恆 1 幀(第 1 次 push 的前半窗是歸零歷史)。center = 1:第 1 次 push 0 幀、第 2 次 2 幀、之後 1 幀,輸出緩衝區要容納 2 幀;ac_stft_flush() 吐尾端 reflect 幀(回 1,不足兩個 hop 回 0)
AcIstft 輸出AC_OLA_ACCUMULATE:每幀吐 hop 個樣本。AC_OLA_ENV_NORM:acc／max(env, 1e-11f);第 1 幀吐 0 個;ac_istft_flush() 吐 hop 個尚在 overlap 內的樣本(不推進狀態)。輸入頻譜不會被修改
別名輸出緩衝區不得與輸入重疊;ac_stft_frame() 的 frame 是呼叫端自備的 N 樣本,不改變歷史
延遲恆等串接 = hop 個樣本(ac_stft_latency_samples())
記憶體只有 static 路徑,無 heap、無 destroy;pool 16-byte 對齊。init 對髒 pool 與全零 pool 給出相同輸出(test_stft 檢查)
目前 pipelines 與 NN 前後處理仍各自持有等價的組幀實作;test_stft 以這些實作的逐行複本驗證本物件:pipeline 合成與 centered 分析／包絡正規化合成逐位元相同,DFN2／GTCRN 的正規化頻譜版分析頻譜逐位元相同、合成輸出只差偶發的 ±0.0 符號(報告見 test_stft 的 B| 輸出列)。

4. hpf.h — 高通濾波器設定

Hpf *hpf = hpf_create(80.0f, 16000);   /* 或 hpf_get_mem_size() + hpf_init() */
hpf_process(hpf, buf, n);              /* 只有就地一種模式,mono */
hpf_reset(hpf);                        /* 換串流時;係數不變,只清狀態 */
hpf_destroy(hpf);
項目契約 / 效果
形式二階、12 dB/oct rolloff、Direct Form II transposed
cutoff_hz 定義域finite、> 0、且嚴格 < 0.45 × sample_rate(不是 0.5——留給雙線性轉換 tan(π·f/sr) 的 well-conditioned margin)。16 kHz → 上限 7200 Hz
不合法時回 NULL,不會產生退化係數
hpf_get_mem_size()不帶參數——大小與截止頻率無關
聲道mono only。多聲道要各自建一個 Hpf 並先去交錯
調高 cutoff 的效果風噪、桌面震動、低頻隆隆更乾淨;但調過頭(如 >150 Hz)會削掉男聲基頻,聽起來變薄
AEC 已經內建 mic-path HPF(AecConfig.enable_highpass 預設 1、highpass_cutoff_hz 預設 80),而且 far/ref 路徑刻意沒有 HPF。要在 AEC 之外再做一層之前,先確認你不是在重複同一件事——見 AEC 參數 §8.2。

5. audio_pre_gain.h — 輸入 gain 設定

AudioPreGain *g = audio_pre_gain_create(-6.0f);   /* 振幅 dB */
audio_pre_gain_set_db(g, -3.0f);                  /* 執行期可改 */
audio_pre_gain_process(g, buf, buf, n);           /* 就地可用 */
audio_pre_gain_destroy(g);
項目契約 / 效果
dB 換算振幅 dB:linear = 10^(gain_db/20)。只在 create／init／set_db 時換算一次,process 每樣本一次乘法
不裁切正增益可能讓樣本超出 [-1,1]。溢位政策完全是呼叫端責任
就地input == output(完全同一指標)可用;部分重疊不支援
執行期可改audio_pre_gain_set_db() 是有驗證的入口
⚠ 錯誤慣例例外audio_pre_gain_get_db()／_get_linear() 在 handle 為 NULL 時回 NaN,不是 -1。必須用 isnan() 判斷

多聲道要用 FixGain(在 Audio_ALG,不在這裡)

AudioPreGain(audio_common)FixGain(Audio_ALG/pipelines/third_party/gain/fix_gain.h)
聲道mono多聲道,per-channel gain 表
Clipping無選配 enable_clip + clip_value
執行期改值可以(set_db)不行——沒有 retune 路徑,改值要重建 instance
怪癖—global_gain 剛好為 0 會被改寫成 1.0 而非靜音(沿用舊行為)。要靜音請用 enable 旗標
Gain 設定會直接改變 AEC 行為。把 pre-gain 調到讓 ref 常態接近滿刻度,會觸發 AEC 的飽和偵測(saturation_threshold 預設 0.95)並讓線性模型失準 → ERLE 下降。調 gain 之後請重新確認回音消除量。

6. audio_resampler.h — 串流重取樣

AudioResampler *r = audio_resampler_create(48000, 16000, 1);
int cap = audio_resampler_output_bound(r, in_frames);   /* 不要自己按比例算 */
int consumed = 0, produced = 0;

if (audio_resampler_process(r, in, in_frames, out, cap,
                            &consumed, &produced) != 0) { /* error */ }
/* consumed < in_frames → 剩下的必須下次重送 */
項目契約
合法取樣率僅 8000 / 16000 / 24000 / 32000 / 48000;最多 8 聲道
單位input_frames／output_capacity_frames 是 frame 數,不是樣本數;buffer 是交錯 float32
推進不能假設一次吃完 input。一定要用 consumed／produced 推進
輸出容量用 audio_resampler_output_bound()。自己按比例算會偶發少一個 frame(實測 48k→16k、480 frames:bound 161、實際 160)
重疊不同 rate 時 in/out 不可重疊;相同 rate 是精確 memmove 直通,此時重疊安全
reset()只在真的要丟棄整段串流歷史時呼叫(換檔/重啟),不要在一般 block 邊界呼叫
延遲audio_resampler_latency_input_frames(),以輸入 frame 為單位

7. wav_io.h — 只給離線工具

不要放進即時路徑:用 stdio + malloc,每樣本一次 fread/fwrite。
項目契約
接受格式只有 PCM16(audio_format=1,bits=16)與 IEEE float32(=3,bits=32);channels ∈ [1,8]
wav_read_float()永遠只回第一個聲道,其餘被跳過
寫入風格編譯期 WAV_IO_WRITER_STYLE(必須在 include 之前定義):_AEC(預設,PCM16 四捨五入遠離零;AEC_OUT_FLOAT=1 環境變數可切成 float32 直通)vs _NR(永遠 PCM16,直接截斷)。兩風格輸出位元組不同
非有限樣本讀入 float32 的 NaN/±Inf 換成 0.0f 並計入 nonfinite_sanitized;寫 PCM16 同樣清洗;float32 輸出路徑不清洗
擁有權wav_finalize_write() 無論成敗都消耗 handle(關檔+釋放),之後不可再用

8. simd_kernels.h — 共用核心(一般不要直接呼叫)

這是 NR／AEC／audio_common 自己熱路徑內嵌使用的核心層。現有 sk_* 核心:

函式做什麼可就地別名
sk_ema_f32state[i]=α·state[i]+β·x[i]state 就地;x 須不重疊
sk_capply_gain_f32out[i]=z[i]*g[i](複數×實數增益)out==z 可
sk_cadd_f32複數逐項加不可
sk_sq_scale_f32out[i]=x[i]²·scale不可
sk_min_f32 / sk_clip_f32逐項取小 / 就地夾限clip 本就就地;min 不可
sk_fast_sqrt_f32fast_sqrt 陣列版不可
sk_fast_exp_f32 / _exp_neg / _log / _log10 / sk_exp1_approx_f32fast_math 對應陣列版前四者 out==x 可;sk_fast_log10_f32 不可(唯一例外)
sk_mcra_noise_update_f32逐 bin 權重的 MCRA 噪聲 EMA 更新noise_psd 就地
sk_wola_accumulate_f32acc[i]+=x[i]*w[i](OLA 累加)不可
sk_clip_scale_to_s16 / _arrfloat[-1,1]→int16 PCM—
sk_cmag_f32⚠ 名為 mag 但實際是 x.r²+x.i²+eps(功率+floor,沒開根號)不可
sk_linear_to_db_f3210·log10f(x),刻意沒有 NEON 路徑(避免混用近似 log10)不可
sk_asym_ema_f32上升/下降不同係數的非對稱 EMAs 就地
sk_scale_f32out[i]=x[i]*g(單一 broadcast 增益)out==x 可

若你的迴圈形狀跟上表都不一樣,就不要硬套。

9. 建置與連結

make -C audio_common lib BACKEND=ne10 SIMD=1     # 產品
make -C audio_common lib BACKEND=kiss SIMD=0     # 參考建置

消費端至少要帶:

-std=gnu99 -ffp-contract=off
-I<audio_common>/include
<libaudio_common.a> -lm
要點說明
Backend 顯式指定不要靠自動偵測交付。自動偵測是「目標具 ARM NEON → ne10,否則 kiss」
SIMD_KERNELS_FORCE_SCALARarchive 與你的 TU 的定義狀態必須一致
禁用-Ofast／-ffast-math 會改變遞迴 DSP 數值與 parity
archive 路徑由 build flags hash 決定,用 make -s ... print-lib-path 取得,不要自行拼 bin/
audio_common/Makefile 宣告了 NO_STDIO／DEBUG 但不消費它們;本 library 也沒有任何 stage-timing／log／status API。可觀測性請往上層(AEC／pipeline)取——見 串接範例 的 DEBUG 章節。

10. 整合檢查清單

  • 所有 pool 基底 16-byte 對齊;_get_mem_size() 與 _init() 回傳值都檢查。
  • FftHandle／Hpf／AudioResampler／AcStft／AcIstft 在整段串流期間存活,沒有逐 block 重建。
  • FFT 的 forward/inverse 沒有任何 buffer 重疊(含相同指標)。
  • fft_inverse 之後沒有再自己除以 N。
  • Resampler 用 output_bound() 配容量,並依 consumed/produced 推進。
  • HPF cutoff < 0.45 × sample_rate;多聲道各自一個 instance。
  • pre-gain 之後有自己的溢位處理(本模組不裁切)。
  • get_db()／get_linear() 的失敗用 isnan() 判斷,不是比 -1。
  • archive 與 application TU 使用相同 BACKEND／SIMD／FP 旗標。
