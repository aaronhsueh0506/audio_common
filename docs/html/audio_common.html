audio_common — 共用 DSP 層(FFT wrapper 等)

概要

audio_common 是 AEC / NR / Audio_ALG pipelines 共用的 DSP 底層,與 Audio_ALG 同層的獨立 repo(引用時 -I audio_common/include + 連結 libaudio_common.a)。本頁聚焦 FftHandle 契約與零 heap 慣例;STFT/ISTFT 框架(audio_stft.h)見 API 用法節;其餘模組(fast_math、simd_kernels、HPF、pre-gain、resampler、wav_io)列於檔案節。

  • 一個公開 API、兩個後端:KISS(可攜參考、bit-reproducible、host/CI 用)與 NE10(ARM NEON、嵌入式用)。後端是 build 旋鈕(make BACKEND=kiss|ne10)不是分支屬性;不明示 BACKEND= 時依編譯目標自動偵測(__ARM_NEON/__aarch64__)→ 有 NEON 選 NE10,否則退回 KISS。2026-08-18 起在 NEON 目標上這使自動偵測預設變成 NE10(之前預設 KISS);KISS 仍是需要逐位元可重現時的明示可攜參考後端,交付/交叉編譯建議永遠明示 BACKEND=。NE10 與 KISS 輸出不逐位元相同;所有 vs-Python parity 保證僅限 KISS。同一後端下 heap 與 static 路徑 byte-equal(selftest 實測)。
  • FP 政策:-ffp-contract=off 是四 repo 統一政策,每個 Makefile 把它放在 CFLAGS 最後且在 parse 期擋掉 -ffast-math/-Ofast/自帶 -ffp-contract 的覆寫;scripts/audit_fp_contract.sh 用反組譯證明無自動 FMA。
  • float32 全面政策:production 路徑全 f32(唯一例外:KISS 在 plan 期以 double 算 twiddle;NE10 後端連 init 都無 double)。

API 用法

#include "fft_wrapper.h"

/* 靜態路徑(嵌入式;get_mem_size 含後端 twiddle/cfg 的每一個 byte) */
size_t bytes = fft_get_mem_size(512);        /* 0 = fft_size 不在白名單 */
FftHandle* h = fft_init(pool, bytes, 512);   /* pool 16-byte 對齊 */
/* 或 heap:FftHandle* h = fft_create(512); */

int n_freqs = fft_get_n_freqs(h);            /* 512/2+1 = 257 */

float   time_buf[512];
Complex spec[257];
fft_forward(h, time_buf, spec);   /* 未正規化 rfft;buffer 不得重疊(restrict) */
fft_inverse(h, spec, time_buf);   /* irfft × 1/N(兩後端同約定) */

/* 輸入可拋棄時的免防禦性複製版本(輸入內容呼叫後未定義): */
fft_forward_scratch(h, scratch_time, spec);
fft_inverse_scratch(h, scratch_spec, time_buf);

fft_destroy(h);   /* fft_init 的 handle:真 no-op、可重複呼叫 */

FftHandle 契約重點:

  • fft_size 必須是 2 的冪且在 [16, 8192](兩後端一致拒絕範圍外,回 0/NULL)。
  • handle 為 caller-owned:誰配置誰持有,函式庫不藏全域 state;一支 handle 可被多個模組共借——AEC 整個實例(main filter、shadow filter、aec3_post)只carve一支 FftHandle(AEC make test-shared-fft-handle 以指標相等實測,63 checks)。
  • 正規化約定:fft_forward = 未正規化 rfft;fft_inverse = irfft × 1/N。KISS 手動除 N;NE10 的 c2r 自動縮放只因為 Makefile 明確 pin 了 NE10_DSP_RFFT_SCALING(round-trip 驗證過)——不要在沒有它的情況下編 NE10。
  • fft_forward/fft_inverse 參數帶 restrict:輸入輸出不得重疊(全 repo call site 已稽核);需要就地風格用 *_scratch 變體。
  • 純函式 helpers(無 state):fft_magnitude / fft_power / fft_apply_gain(fft_phase / fft_from_mag_phase 已宣告但目前全 repo 無呼叫者——見標頭註解)。

sqrt-Hann 慣例:四 repo 共用的是「window = sqrt(periodic Hann)(denom = N、sym=False),50% overlap 即 COLA、無需再正規化」這個約定。audio_common 以 ac_window_build(w, n)(audio_stft.h)提供這張表,公式 sqrtf(0.5f * (1.0f - cosf(2.0f * pi * k / N)))。目前 AEC lib/aec/c_impl/src/pbfdkf.c(sqrt_hann)、NR 範例 lib/nr/c_impl/example/main_mem.c(build_sqrt_hann())與各 pipeline／NN 前後處理仍各自持有等價建表;test_stft 在 2 的冪 N ∈ [16, 8192] 的每個 N(10 個尺寸,每種公式共 16,368 個元素)逐位元比對 ac_window_build 與 7 種建表公式:mono／4ch pipeline 與 pbfdkf(3 種,49,104 個元素),以及 DFN2、GTCRN、rate bridge 與 ULCNet 的公式(4 種,65,472 個元素;ULCNet 以執行期尺寸版比對),全部 0 bit 差;ULCNet 編譯期固定尺寸的複本另在 N = TEST_N(512、1024)比對。

STFT / ISTFT(audio_stft.h):一對物件取代各處重複的組幀／overlap-add 實作。AcStft 每次吃 hop = N/2 個樣本、吐加窗 rFFT 幀;AcIstft 吃一幀頻譜、吐 hop 個完成的樣本。靜態記憶體(get_mem_size + init,無 heap、無 destroy);FFT handle 與窗表可借用(cfg.fft/cfg.window 非 NULL,借用的 handle 可被多個物件共用,呼叫須循序)或由 pool 自帶(NULL)。

#include "audio_stft.h"

AcStftConfig cfg;
ac_stft_config_default(&cfg, 512);   /* hop = 256;center=0、AC_OLA_ACCUMULATE、scale=1.0f、自帶 FFT 與窗 */
size_t sa = ac_stft_get_mem_size(&cfg);    /* 0 = 設定不合法(fft_size 非 2 的冪、不在 [16,8192]、借用 handle 大小不符…) */
size_t ss = ac_istft_get_mem_size(&cfg);
AcStft  *an  = ac_stft_init(pool_a, sa, &cfg);   /* pool 16-byte 對齊;NULL = 失敗 */
AcIstft *syn = ac_istft_init(pool_s, ss, &cfg);

Complex spec[2 * 257];                       /* center=1 時一次最多 2 幀 */
float   hop_in[256], hop_out[256];
int n = ac_stft_push(an, hop_in, spec);      /* 回傳本次幀數;幀 f 在 spec + f * 257 */
/* ...處理 spec[0..n)... */
for (int f = 0; f < n; ++f)
    ac_istft_push(syn, spec + f * 257, hop_out);   /* 回傳寫出的樣本數:hop,或 ENV_NORM 的第 1 幀回 0 */
用途設定行為
pipeline 合成端(accumulate→emit→shift→尾端清零)預設值每幀吐 hop 個樣本(含第 1 幀);不縮放頻譜
NN 正規化頻譜(DFN2:spec_scale = 1/sqrtf(N)、ispec_scale = sqrtf(N);GTCRN:兩者 1.0f)center = 0、AC_OLA_ACCUMULATE、spec_scale/ispec_scale縮放發生在前向 FFT 之後、反向 FFT 之前的每個 bin;scale 恰為 1.0f 時略過乘法(bin 為精確搬移,NaN payload 與 −0.0 不變)
torch.stft(center=True, reflect) / torch.istft 語意(Align-ULCNet、AIAEC)center = 1、AC_OLA_ENV_NORM分析:第 1 次 push 0 幀、第 2 次 2 幀(reflect 前綴幀 + 第 1 幀)、之後每次 1 幀;ac_stft_flush 補尾端 reflect 幀。合成:同時累加窗平方包絡,輸出 acc / max(env, 1e-11f);第 1 幀落在被裁掉的半窗,不吐樣本;ac_istft_flush 吐出 hop 個尚在 overlap 內的樣本

其他入口:ac_stft_push_planar / ac_istft_push_planar(re、im 分開的陣列,多幀時第 f 幀在 re + f * n_freqs)、ac_stft_frame[_planar](對呼叫端自備的 N 樣本幀做加窗 rFFT,不碰歷史,例如 FIFO 取幀的橋接器)、ac_stft_window()/ac_istft_window()(取得使用中的窗表以便共用)、ac_stft_reset()/ac_istft_reset()、ac_stft_latency_samples()。同一個 AcStft 的 center 在建立時固定,兩種框架不可共用一個物件。

零 heap 慣例(全模組一體適用):每個模組都有 heap 路徑(X_create/X_destroy)與 static 路徑(X_get_mem_size(...) + X_init(void* mem, size_t mem_size, ...)),runtime 以 pool_owned/is_static 旗標區分、無編譯期開關;get_mem_size 與 init 必須以相同順序走欄位(對齊 ALIGN16,見 mem_align.h);X_destroy 對兩路徑都安全(pool 實例不 free 任何東西)。fft_get_mem_size 涵蓋 fft_init 會碰的每一個 byte(含後端內部 cfg),兩後端在 init 路徑上完全不碰 heap(test_fft_zero_heap 以 allocator hook 實測)。

延遲與 warm-up

  • fft_forward/fft_inverse:單呼叫內完成,0 樣本延遲、無 warm-up。WOLA 框架的 1 hop 延遲屬於 consumer 的組幀/OLA 慣例(見泳道圖),不屬於本函式庫。
  • AcStft → AcIstft 恆等串接:延遲 = hop = fft_size/2 樣本(ac_stft_latency_samples()),center 0/1 相同。實測(test_stft,arm64 主機上的四種 build,輸入為固定種子的隨機訊號):N = 64、256、512、1024 時 impulse 延遲為 hop(32、128、256、512 樣本);N ≤ 1024 的重建最大絕對誤差皆小於 5e-7,數值隨 N 與 FFT 後端而變,與 TEST_N 無關,實測如下(test_stft 的判定門檻為 1e-6)。
